A measurement · September 2026

I ran my own e-invoices through Germany’s official validator. The first run failed six rules.

I build an e-invoicing plugin for WooCommerce, so read this with that in mind. The measurement is reproducible, and the tool at the end is free and needs no sign-up.

What I assumed

Most WooCommerce invoice plugins produce the XML, and several produce it for nothing. I assumed mine was fine. The unit tests were green. The library is well regarded. The output validated against EN 16931.

Then I downloaded KoSIT’s official validator configuration — the same Schematron a German authority runs — and pointed it at my own output.

What came back

Six rules failed. Every one of them a field the European standard leaves optional and Germany makes mandatory:

RuleWhat it wants
BR-DE-5Seller contact point (BT-41)
BR-DE-6Seller contact telephone number (BT-42)
BR-DE-1Payment instructions (BG-16)
BR-DE-27The telephone number may not be blank
PEPPOL-EN16931-R020Seller electronic address (BT-34)
PEPPOL-EN16931-R010Buyer electronic address (BT-49)

My invoice was valid EN 16931 and would have been refused in Germany. My own tests could not have told me that, because they were testing the wrong thing: the standard, not the country.

Why this gap exists at all

The rule set that decides whether a document is accepted compiles to XSLT 2.0. PHP’s XSL extension only speaks XSLT 1.0. A WordPress plugin therefore cannot run it in-process — not as a shortcut, not with more effort. It is genuinely easy to ship something that looks right and is refused.

That is not a criticism of any particular plugin. It is the reason the problem is invisible: the software that produces the file is structurally unable to check it.

Repeat it on your own invoice

I fixed the six, and then put the validator behind a page so anyone can run the same measurement without installing anything.

Check an invoice Get the free plugin

Paste an invoice — from my plugin or any other — and see what the official rule set says. No sign-up, nothing stored.

A fair question to ask any vendor

If you already use an e-invoicing plugin, the useful question to put to its author is simply: can I see your validator report?

That is a fair question to ask anyone selling this, me included. Mine is in the repository, with the failures written down as well as the fixes.
